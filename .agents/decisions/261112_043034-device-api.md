# Decision: Device and rack API

Status: accepted

## Background

- P0 must fix the API that device authors and application builders use.
- The API must meet the constraints in the architecture decision:
  - Devices are mounted by path.
  - Devices interact with each other only through backplane addresses.
  - Background tasks run only after `activate`.

## Decision

### Connectors

```ts
import * as v from "valibot";
import { connector, rpc, event } from "rack42u";

export const Kv = connector("kv/v1", {
  get: rpc(v.string(), v.nullable(v.string())),
  set: rpc(v.object({ key: v.string(), value: v.string() }), v.undefined()),
  changed: event(v.object({ key: v.string() })),
});
```

- In `connector(id, members)`, `id` has the form `<name>/v<major version>`. The name consists of lowercase letters, digits, `.`, and `-`, for example `kv/v1` and `acme.orders/v2`.
- Members come in two kinds:
  - RPC methods: `rpc(input schema, output schema)`.
  - Events: `event(payload schema)`.
- Member names must be valid JavaScript identifiers.
- A schema can be any object that implements Standard Schema, for example a valibot or zod schema.
- An incompatible change must bump the major version, that is, use a new `id`.

### Devices

```ts
import { device } from "rack42u";

export default device({
  model: "orders",
  height: 2,
  needs: { db: Sql, cache: Kv },
  provides: { api: OrdersApi },
  config: v.object({ currency: v.string() }),
  powerOn(ctx) {
    return { api: { async create(input, call) { /* ... */ } } };
  },
  activate(ctx, scope) {
    scope.every(30_000, () => ctx.log.info("tick"));
  },
  snapshot(ctx) { return { /* ... */ }; },
  restore(ctx, state, fromFirmware) { /* ... */ },
});
```

- One device per file, exported with `export default device({...})`.
- Fields:
  - `model`: the model name.
  - `height`: the number of U slots occupied, default 1.
  - `config`: optional configuration schema; the rack uses it to validate the configuration when the device loads.
- `powerOn` returns the implementation of each port in `provides`: each RPC member maps to a function `(input, call) => output`.
  - `input` has already been validated.
  - When the caller cancels or the call times out, `call.signal` is aborted.
  - `call.deadline` is the deadline (a millisecond timestamp).
- All other hooks are optional; see [Lifecycle](261112_035943-hot-swap.md#lifecycle) for their meaning.
- The state that `restore` receives comes from the old firmware and may differ in shape from the current version, so the device should validate it itself.

### Device context

The first argument of a hook, `ctx`, provides the following:

- **`ctx.ports.<need>.<method>(input, options?)`**: calls an RPC method of a needed connector and returns a Promise. `options` can set `timeout` (milliseconds) and `signal`.
- **`ctx.on.<need>.<event>(handler)`**: subscribes to an event of a needed connector and returns a function that unsubscribes. Events are delivered only to the instance currently installed.
- **`ctx.emit.<port>.<event>(payload)`**: publishes an event on a port provided by this device and returns a Promise; the Promise is rejected when payload validation fails.
- **`ctx.config`**: the validated configuration.
- **`ctx.log.debug/info/warn/error(message, data?)`**: writes a log entry; logs are aggregated to the rack through the management bus.
- **`ctx.signal`**: aborted when the instance is powered off.
- **`ctx.slot`, `ctx.firmware`, `ctx.baseDir`**: respectively `{ name, u }`, the firmware version of this instance, and the base directory of the rack.
- **`process.env`**: when the Worker that hosts the device is created, it receives a copy of the main thread's environment variables at that moment.

The second argument of `activate`, `scope`, provides the following:

- **`scope.signal`**: aborted on `deactivate`.
- **`scope.every(ms, task)`, `scope.after(ms, task)`**: timers managed by the rack that stop automatically on `deactivate`. Errors thrown by a task are only logged and do not crash the device.

### Rack manifest

```ts
import { rack, slot } from "rack42u";
import { memkv, sqlite } from "rack42u/std";

export default rack("shop", {
  size: 42,
  slots: {
    1: sqlite({ path: "data/shop.db" }),
    3: memkv(),
    5: slot("./devices/orders.ts", { name: "orders", config: { currency: "USD" } }),
  },
  patch: [["orders.cache", "memkv.kv"]],
  panel: { http: { port: 3000, routes: { "/api/*": "orders.http" } } },
});
```

- In `slot(source, options?)`, `source` is the path to the device file, either a string or a `URL`; a relative path resolves against the base directory of the rack.
- A device name defaults to the model name. Device names must be unique within a rack; when several devices share a model, use `name` to tell them apart.
- Each entry of `patch` is `[<consumer device>.<need>, <provider device>.<port>]`.
- A standard device's factory function (such as `memkv()`) returns only a mount description; the main thread does not load device code because of it.

### Rack runtime

```ts
import { start } from "rack42u";
import manifest from "./rack.ts";

const running = await start(manifest, { baseDir: import.meta.dir });
```

- `start(manifest, options)` builds the firmware, powers on every device in order, opens the panel, and then returns the rack handle.
- The handle provides the following methods:
  - `status()`: shows the state of each slot.
  - `call(address, method, input, options?)`: calls a port from outside the rack, for testing and management.
  - `reload()`: rebuilds all firmware and replaces only devices whose hash changed.
  - `swap(name, source?)`: replaces the given device, possibly with a different device file.
  - `plug(u, slotSpec)`, `unplug(name)`: plugs in and unplugs a device.
  - `subscribe(listener)`: receives rack events, including power transitions, swaps, faults, and logs.
  - `stop()`: shuts down in order.
- Options and defaults:
  - `baseDir`: defaults to the current working directory.
  - `logger`: log output.
  - `callTimeout`: call timeout, default 30 seconds.
  - `hookTimeout`: lifecycle hook timeout, default 30 seconds.
  - `drainTimeout`: drain timeout, default 10 seconds.

### Panel HTTP

- `panel.http.routes` maps Bun route patterns (such as `/orders/:id` and `/api/*`) to ports that implement `http/v1`.
- `http/v1` has a single RPC method, `handle`:
  - Input: `{ method, url, headers, params, body }`.
  - Output: `{ status, headers, body }`.
  - `headers` is an array of `[name, value]` pairs, used to preserve duplicate headers such as several `Set-Cookie` headers.
  - `body` is a `Uint8Array` or `null`.
- `httpHandler(fetch)` wraps a function of the form `(request: Request) => Response` into an implementation of `http/v1`, so existing routing libraries can be used directly in a device.
- Backplane errors map to HTTP status codes: `RACK_LINK_DOWN` maps to 503, `RACK_TIMEOUT` maps to 504, and any other error maps to 502. The response body is JSON: `{ code, message }`.

### Command line

- `rack start [manifest path]`: starts the rack; the manifest path defaults to `rack.ts`.
- `rack dev [manifest path]`: starts the rack and reloads automatically when files change.
- On `SIGINT` or `SIGTERM`, shut down in order first, and then exit.

## Alternatives

- **Let the manifest import device modules directly**: this makes type checking easier, but the main thread would then load device code, which violates [The main thread never loads device code](261112_035943-hot-swap.md#the-main-thread-never-loads-device-code).
- **Put event subscription on `ctx.ports.<need>.on(...)`**: it would collide with an RPC method named `on`. A separate `ctx.on` namespace avoids the collision.
- **Let the panel map HTTP routes directly to arbitrary RPC methods**: this needs rules for how path parameters, query strings, and request bodies are assembled into input; the rules are complex, and it only suits JSON APIs. A single `http/v1` port can carry any HTTP application, including frontend pages and existing routing libraries.
- **Give the state of `restore` a type parameter**: the state shape of old firmware may differ, and a type parameter would give a false sense of safety, so it is `unknown`.

## Impact

- The manifest does not import devices, so P0 cannot check at compile time whether the wiring matches; it can only validate at startup and during a swap and report an error.
- When a device handles a request through `http/v1`, both the request body and the response body are copied once in full; P0 does not support streaming.
- The public API is bound by this decision from now on; adding, removing, or changing it requires a new decision first.

## Implementation

- Connectors: `connector`, `rpc`, `event`, and `describeConnector` in `src/connector.ts`, tested in `test/connector.test.ts`.
- The device, rack manifest, rack runtime, panel, and command-line APIs are not implemented yet.
