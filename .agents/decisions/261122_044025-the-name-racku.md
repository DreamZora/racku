# Decision: The project and its package are named racku

Status: accepted

## Background

- [The first formal release](261122_005312-first-formal-release.md#the-package) publishes the package to npm as `rack42u`, a name that npm's registry answered 404 for on 2026-11-22.
- When the user accepted that decision, on 2026-11-22, they asked: "If the name rack is not already taken, rename rack42u to rack before publishing to npm." The registry answered 200 for `rack`: a package of that name since 2011, at 0.1.6.
- The user then wrote: "`rack` is taken, but `racku` isn't, so we can rename rack42u to racku and then publish."
- On 2026-11-22 the registry answered 404 for `racku`, and for `rack-u`, `rack_u`, `rack.u`, `rac-ku`, `ra-cku`, and `r-acku`. npm refuses a new name that matches an existing one once its punctuation is removed, so those spellings would have blocked `racku` too.
- The name `rack42u` is in:
  - the package's name, its entry points, and the import specifiers of every device file, connector, and test;
  - the documentation, the skill, and `AGENTS.md`;
  - the control directory's path;
  - the global symbols of executables, and the names of temporary files and test variables;
  - net-tool's app identifier, which names its directories;
  - the trials' workflow;
  - the repository's name on GitHub.
- No app outside this repository depends on rack42u, and every version so far is informal, so any of them may break the API.

## Decision

### What is named racku

- The project and its package are named **racku**, and so are its entry points: `racku`, `racku/std`, and `racku/bench`.
  - Device files, connectors, and tests import them by those names.
  - Firmware keeps them outside its bundle, as it kept `rack42u`.
- 1.0.0 is published to npm as `racku`, where [the day of the release](261122_005312-first-formal-release.md#the-day-of-the-release) says `rack42u`.
- What else carries the project's name follows it:
  - the README, the documentation, `AGENTS.md`, and the issue forms;
  - the skill: in `skills/racku/`, and named `racku`; apps copy it from `node_modules/racku/skills/racku/`;
  - the control directory: `$XDG_RUNTIME_DIR/racku/`, `~/.local/state/racku/control/`, and `%LOCALAPPDATA%\racku\control\`;
  - the global symbols of executables, the prefixes of temporary files and directories, and the environment variables of tests, such as `RACKU_TEST_ENV`;
  - net-tool's app identifier, `dev.racku.net-tool`, which names its directories on each system;
  - the trials' workflow, `racku-trials`, and what the trial agents are told.

### What keeps its name

- **The rack's own names**, which come from its terms, not from the project's name:
  - the `rack` command;
  - the error codes `RACK_*`, and the environment variables `RACK_*`, such as `RACK_CONTROL_TOKEN`;
  - the directory `.rack/`.
- **The repository**, `DreamZora/rack42u`, until the user renames it on GitHub. Its URLs then change in one commit, and GitHub redirects the old ones.
- **The records of the past:**
  - the decisions before this one;
  - the informal tags v0.1.0 to v0.6.0, whose package is named rack42u;
  - the issues #1 to #22;
  - the second round's trial apps and their records, until the next round clears them.
- Where an earlier decision says rack42u, it means racku.

### Versions

- A tag from v0.1.0 to v0.6.0 installs a package named rack42u; the next one installs racku. An app that moves from one to the other changes its dependency and its imports.
- Getting started names a tag of racku once there is one. Every tag waits for the user's word, as before.

### Where this decision changes others

- [The first formal release](261122_005312-first-formal-release.md): the package is published as `racku`.
- Every decision before this one that names rack42u, as above.

Each of them stays, and this decision comes first where they differ.

## Alternatives

- **Keeping `rack42u`.** It is free on npm, and nothing would change. Not chosen: the user chose racku.
- **A scoped name with `rack` in it, such as `@<account>/rack`.** Every import would carry the scope, which is the name of an npm account or organization. Not chosen.
- **Renaming the `rack` command and the `RACK_*` names too.** They name the rack, not the project. And `rack` is the command that scripts and the guides run. Not chosen.

## Impact

- **Breaking:**
  - imports change from `rack42u` to `racku`;
  - the skill moves to `skills/racku/`;
  - the control directory moves, so `rack ctl` of racku doesn't find a rack of an earlier version.
- **Changed:**
  - every file that names the project, as listed above;
  - `bun.lock`, which names the root package.
- **For the user:** renaming the repository on GitHub, if they want it renamed, and publishing `racku` on the release day.

## Implementation

- The rename: `710c5eb`.
- The user renamed the repository to `DreamZora/racku` on 2026-11-22, as [The repository is public before the first formal release](261122_062703-public-before-the-first-release.md) records; the URL of `package.json`, getting started, and the skill name it since.

- The Agent chose what keeps its name: the rack's own names, the repository until the user renames it, and the records of the past.
